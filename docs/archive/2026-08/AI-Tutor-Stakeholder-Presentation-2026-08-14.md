# AI-Tutor MVP — презентация для стейкхолдера

_Дата: 2026-08-14_  
_Язык: простой, не технический_

## Короткий вывод

AI-Tutor уже доведён до рабочего MVP: есть ученик, родитель, учитель, администратор, готовая математика 42/42, мониторинг, backup и production-контур. Следующий этап — не добавлять хаотично новые функции, а доказать пользу на живом math-пилоте и потом масштабировать проверенный шаблон.

---

## 1. Что сделано по итогам проекта

| Направление | Что сделано | Что это даёт простым языком |
|---|---|---|
| Рабочий продукт | Приложение работает на production-домене, есть основные пользовательские роли | Можно тестировать реальный сценарий, а не макет |
| Ученик | Есть предметы, темы, урок, объяснение, чат, практика, следующий шаг | Ребёнок понимает, что делать дальше |
| Математика | Подготовлены все 42 темы предмета “Математика, 6 класс — повторение” | Есть полноценная база для пилота |
| Источники | У всех математических тем есть проверенная привязка к материалам | Ответы не выглядят как “из воздуха” |
| Практика | У тем есть проверяемые задания и follow-up кнопки | Можно тренироваться, а не только читать объяснения |
| Диагностика | Добавлен math-маршрут и контрольные темы | Система помогает начинать с правильных слабых мест |
| Родитель | Есть сводка прогресса и рекомендации | Родитель понимает, где ребёнку помочь |
| Учитель | Есть управление материалами и готовностью тем | Можно улучшать качество, а не править всё вручную в коде |
| Админ | Есть пользователи, инвайты, аудит, monitoring | Проектом можно управлять безопаснее |
| Надёжность | Backup, offsite, Prometheus/Grafana, health-checks | Меньше риска потерять данные или не заметить сбой |

**Итог текущей фазы:** MVP готов к осмысленному ручному тестированию в рамках математики.

---

## 2. Что предстоит сделать в ближайший месяц

| Приоритет | Что делаем | Что это даст пользователю |
|---:|---|---|
| P0 | Провести живой пилот с учеником | Проверим, как продукт работает не в тесте, а в реальном обучении |
| P0 | Вычитать все задания и объяснения по математике | Ребёнок увидит понятные школьные формулировки |
| P0 | Добавить больше вариантов практики | Задания не будут повторяться слишком быстро |
| P0 | Настроить adaptive progression по ошибкам и mastery | Система начнёт вести как репетитор: повторять слабое и двигать дальше |
| P1 | Сделать еженедельный отчёт для родителя | Родитель видит: что освоено, где проблема, что делать завтра |
| P1 | Улучшить teacher review mode | Учителю проще отметить: “годится”, “переписать”, “добавить пример” |
| P1 | Проверить стабильность после живого использования | Станет понятно, выдерживает ли MVP регулярный пилот |

**Итог месяца:** AI-Tutor должен стать не просто рабочим MVP, а понятным пилотным учебным инструментом.

---

## 3. Что предстоит сделать в ближайшие 3 месяца

| Период | Главный фокус | Что делаем | Что это даст |
|---|---|---|---|
| Месяц 1 | Пилот математики | Живое тестирование, редактура, больше практики, отчёты | Докажем пользу на одном сильном предмете |
| Месяц 2 | Расширение предметов | Перенести шаблон на алгебру и геометрию: источники, маршрут, задания, smoke | Проект перестаёт быть “только математикой” |
| Месяц 3 | Платформа | Аналитика, контроль качества, адаптивный план, масштабирование учеников | Появляется управляемая образовательная система |

**Итог 3 месяцев:** проект должен перейти от ручного пилота к повторяемой платформе, где новые предметы добавляются по понятному стандарту.

---

## 4. Глобальное отличие проекта в каждой фазе

| Фаза | Как выглядит проект | Главное отличие от предыдущей |
|---|---|---|
| Прототип | Есть идея, экран, AI отвечает на вопросы | Проверяем, что идея технически возможна |
| MVP | Есть роли, уроки, математика, родитель, учитель, админ | Появляется полный пользовательский контур |
| Пилот | Реальный ребёнок проходит диагностику, темы и практику | Проверяем пользу в живом обучении |
| Платформа | Несколько предметов, маршруты, аналитика, контроль качества | Масштабируем не хаос, а проверенный процесс |
| Экосистема | Много пользователей, методика, партнёры, внешняя оценка | Проект становится образовательным продуктом, а не внутренним инструментом |

**Ключевая мысль:** каждая фаза повышает не количество экранов, а уровень доверия к учебному процессу.

## Финальная рекомендация

Следующий правильный шаг — **живой math-пилот**, а не распыление на новые функции.

Сначала нужно доказать:

1. ребёнок реально проходит уроки;
2. практика помогает закреплять темы;
3. родитель понимает отчёт;
4. учитель может улучшать качество;
5. система остаётся стабильной после регулярного использования.

После этого можно масштабировать проверенный шаблон на алгебру, геометрию и другие предметы.
