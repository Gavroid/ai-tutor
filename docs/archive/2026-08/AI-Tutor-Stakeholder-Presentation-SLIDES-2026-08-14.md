# 2. Ближайший месяц

| Приоритет | Что делаем | Что это даст пользователю |
|---:|---|---|
| P0 | Живой пилот с учеником | Проверим реальное обучение |

# 2. Как продукт выглядит через месяц

- Ребёнок проходит диагностику и получает маршрут.
- Темы не выбираются случайно — система ведёт дальше.
- У каждой темы есть несколько вариантов практики.
- Родитель получает простой отчёт без технических деталей.
- Учитель видит, что требует правки.

# 3. Ближайшие 3 месяца

| Период | Главный фокус | Что делаем | Что это даст |
|---|---|---|---|
| Месяц 1 | Пилот математики | Живое тестирование, редактура, практика | Докажем пользу на одном предмете |
| Месяц 2 | Новые предметы | Алгебра и геометрия по тому же стандарту | Проект перестаёт быть только математикой |
| Месяц 3 | Платформа | Аналитика, качество, масштабирование | Появляется управляемая система |

# 3. Результат через 3 месяца

- Математика стабилизирована и проверена живым использованием.
- Алгебра и геометрия подготовлены по тому же шаблону.
- Ошибки ребёнка влияют на повторение и следующую тему.
- Учитель управляет качеством материалов.
- Можно подключать больше учеников без ручного хаоса.

# 4. Главная мысль по фазам

Каждая фаза повышает не количество экранов, а уровень доверия к учебному процессу.

- Прототип отвечает на вопрос: “можно ли сделать?”
- MVP отвечает: “работает ли полный сценарий?”
- Пилот отвечает: “помогает ли ребёнку?”
- Платформа отвечает: “можно ли масштабировать?”
- Экосистема отвечает: “можно ли строить вокруг этого продукт?”

# Финальная рекомендация

Следующий правильный шаг — живой math-пилот.

Сначала нужно доказать:

1. ребёнок реально проходит уроки;
2. практика помогает закреплять темы;
3. родитель понимает отчёт;
4. учитель может улучшать качество;
5. система остаётся стабильной после регулярного использования.

После этого можно масштабировать шаблон на алгебру, геометрию и другие предметы.
