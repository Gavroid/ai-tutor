# AI-Tutor — UI аудит

**Дата:** 2026-08-23
**Метод:** Headless Chromium через Playwright → screenshot + manual inspection + сравнение с design-audit 2026-08-20.

---

## 1. Общая оценка UI

**Вердикт:** UI в **хорошем состоянии**. Prism/Split стиль соблюдён, темная тема единая, нет белых панелей, типографика плотная, акцентные цвета (фиолетовый/лавандовый) использованы последовательно.

**Главные UI-проблемы:**
1. **Status confusion** — все 16 предметов имеют одинаковый зелёный бейдж «MVP-ready», даже когда реально контента нет.
2. **MAРШРУТ 17/42** на странице `lit-2` — явная ошибка рендера (число берётся из другого предмета).
3. **Нет visual feedback для blocked_ocr / preview** — пользователь не отличает готовый предмет от preview.
4. **Mobile не проверен** — есть framework, но нет end-to-end проверки в живом мобильном браузере.

## 2. Постраничный UI-обзор

### 2.1 `/login`

**Screenshot оценка:**

✅ **Что хорошо:**
- Разделение на левый brand panel (Prism Tutor logo, заголовок «Вход в учебную систему», описание, три карточки STUDENT/PARENT/TEACHER с одной командой каждая — Learn / Track / Operate) и правый auth-form card.
- Цветовая палитра: чёрный/тёмно-серый фон, лавандовый accent на кнопке «Войти», белый заголовок, голубые подсветки для «учебную», «систему».
- Кнопка «Secure portal» в виде pill-badge.
- Heading typography крупная, сильная, читается с 5 метров.
- «Восстановить» / «Зарегистрироваться» — синие ссылки, чёткие.

⚠️ **Мелкие проблемы:**
- Email input говорит `your@email.com` (хорошо для placeholder), но нет visible label «Email» — он только в title. Это спорно по accessibility (нет `<label for>`).
- Password field label тоже только в title.
- Нет «показать пароль» toggle (приветствие для мобильного использования).
- Нет keyboard hint для авто-submit.

🔧 **Что хочется:**
- Auto-focus на email input.
- «Показать пароль» toggle.
- Submit при Enter (уже есть в стандартной форме, но явно submit button visible state лучше сделать).

### 2.3 `/subjects` (главный каталог)

**Что есть:**
- Header с брендом «Prism Tutor», subtitle «Prism Learning OS», user badge «student · Кирилл», кнопка «Выйти».
- Hero-секция: «EXPLORE · STUDENT MISSION CONTROL», крупный заголовок «Выбери траекторию обучения», описание, кнопки «Диагностика» + «Привязать родителя».
- KPI-блок «LIVE SYSTEM»: ПРЕДМЕТОВ 16, ПИЛОТ 16, В ОБРАБОТКЕ —, OCR-BLOCKED —, AI ON, Модель MiniMax-M3, «Стоит повторить» (3 темы для Кирилла).
- Каталог «SUBJECT GALLERY» с 16 карточками предметов. Каждая:
  - Эмодзи иконка слева
  - Бейдж «MVP-ready» справа сверху
  - Заголовок
  - 1-2 строки описания
  - «Готово: маршрут, источники, практика и ручной smoke закрыты. Доступно пилоту.»
  - 3 метрики: МАРШРУТ X/N, ИСТОЧНИКИ Y/N, ПРАКТИКА Z/N
  - Класс + «ОТКРЫТЬ →»
- Поиск «Поиск: математика, русский, физика…»

✅ **Что хорошо:**
- Плотная, dark, без белых панелей.
- Эмодзи-иконки помогают быстро сканировать.
- Каждая карточка имеет 3 метрики — пользователь видит прогресс до того, как откроет.

❌ **Что плохо:**
1. **Все 16 «MVP-ready».** У Всеобщей истории «ПРАКТИКА 0/10», у Литературы ч.2 «0/17», у Русского ч.2 «0/13», у Химии «0/15». **UI говорит одно и то же независимо от состояния.** Это главная UX-проблема. Ребёнок не отличит, что реально работает.
2. **KPI «В ОБРАБОТКЕ —»** показывает прочерк, хотя фактически такие предметы есть. Карточки и KPI противоречат друг другу.
3. **«OCR-BLOCKED —»** — то же самое. Реально 5 предметов имеют `blocked_ocr` (по evidence.json). Но UI даёт «—».
4. **«Стоит повторить»** показывает 3 темы — но без ссылки на каждую из них (только на список). Это не bug, но UX-шанс.

🔧 **Что хочется:**
- **Status chip per subject:**
  - Готовый предмет: «✅ MVP-ready» (зелёный)
  - В обработке: «⏳ В обработке» (амбер)
  - Blocked OCR: «📚 OCR-заблокировано» (красный)
  - Preview: «🔍 Preview» (нейтральный)
- **Показывать blocked_ocr причину в тултипе** при наведении.
- **Скрыть «Открыть» для non-pilot_visible** для student — только для teacher/admin.

### 2.4 `/subjects/[id]` (страница предмета, e.g. `math` id=3)

**Что есть:**
- Top header: «← Все предметы», иконка + название предмета.
- **READINESS PANEL**: ТЕМ 42, СТАТУС Ready, RAG ON, PRACTICE ON, МАРШРУТ 42/42, КОНТРОЛЬ 5.
- Subtitle: «MVP-ready. Готово: маршрут, источники, практика и ручной smoke закрыты. Доступно пилоту.»
- **TIMELINE** с badges `MVP-ready`, `Base 18, Medium 21, Hard 3`.
- Список из 42 тем в виде link-карточек: номер, заголовок темы, фокус, badge уровня (base/medium/hard), прогресс 2/5, иногда «Контроль».

✅ **Что хорошо:**
- Заголовки конкретные («Среднее арифметическое», «Наименьшее общее кратное», «Прямая и обратная пропорциональные зависимости»).
- Уровни видны на глаз.
- Контрольные темы выделены.
- Прогресс каждой темы.

❌ **Что плохо:**
1. **«МАРШРУТ 17/42» для lit-2.** На странице `Литература (часть 2)` показывается «МАРШРУТ 17/42» — это явная ошибка рендера. 42 — это размер math.route, не lit-2.route. Видимо hardcoded fallback или баг в subjects/[id]/page.tsx.
2. **Нет ссылки на конкретную тему в прогрессе** — формат «2/5» как badge без кликабельности.
3. **В READINESS PANEL для non-math предметов** всё равно показывается `СТАТУС Ready` — даже если practice 0/N.

🔧 **Что хочется:**
- Math route plan dict должен зависеть от subject.code, а не hardcoded 42.
- Если STATUS != Ready — показывать причину под заголовком.
- Прогресс 2/5 → clickable sparkline или pop-up с историей.

### 2.5 `/topics/[id]` (страница урока, e.g. id=120)

**Что есть:**
- Header как везде.
- **УРОК** секция с кнопками «Объяснить» и «Практика».
- **СЛЕДУЮЩИЙ ШАГ**: «Начни с объяснения», описание, кнопки «Начать объяснение» / «Сделать паузу в занятии».
- **ЧАТ С РЕПЕТИТОРОМ**: textarea «Задай вопрос репетитору…» + кнопка «Отправить» (disabled).
- **Практика появится здесь** (заглушка).

✅ **Что хорошо:**
- Структура понятна: урок → практика → чат.
- «Сделать паузу» — T1D-friendly.
- Чат с placeholder-предложением.

❌ **Что плохо:**
1. **После клика «Начать объяснение» UI не обновляется** (Playwright snapshot показал тот же контент через 3 сек). Возможно WebSocket не подключился или AI endpoint вернул ошибку. Это блокер для student-flow.
2. **Текстarea в чате слишком маленькая** — для вопроса типа «объясни дробь от числа через пиццу» нужно больше места и кнопка paste-friendly.
3. **«Отправить» disabled пока ничего не введено** — корректно, но визуально не очень понятно что это кликабельно (нет focus state у disabled).
4. **Нет визуального индикатора, что AI работает** после клика «Объяснить». Должен быть skeleton/spinner/анимация.

🔧 **Что хочется:**
- После клика «Объяснить» — skeleton или «AI печатает...» индикатор.
- Markdown rendering в чате (уже есть SafeMarkdown.tsx, но протестировать визуально).
- Возможность скопировать объяснение.
- Показывать badge «уже отвечали на это» если re-visit.

## 4. Accessibility (a11y) — быстрая оценка

✅ **Что есть:**
- LabelText + textbox + button структура (semantic HTML).
- Form с правильным role.
- Cookie auth не ломает screen reader (cookies screenreader-invisible).

⚠️ **Что отсутствует/плохо (по Sprint 11 F2.4):**
- Нет `<input aria-label>` на textarea чата/ответа.
- Нет `aria-live` на check-result и chat-log.
- Нет `role="log"` для чата.
- Нет skip-link для навигации.
- Нет focus-visible стилей (только :focus браузерный).

🔧 **Что делать:**
1. Добавить aria-label / aria-labelledby.
2. Добавить `<div role="log" aria-live="polite">` для чата.
3. Skip-link к main content.
4. Focus-visible кольца для keyboard users.

## 5. Mobile UX

### Что не проверено в реальном mobile viewport
- `/subjects` — card grid на 4 колонки, на 1 колонке вряд ли ломается, но хедер с навигацией — может требовать hamburger.
- `/subjects/[id]` — список из 42 тем, scroll на узком экране.
- `/topics/[id]` — двусторонний layout (УРОК + ЧАТ + ПРАКТИКА) — на mobile вероятно надо переключатель tabs, не одновременно 3 секции.

🔧 **Что хочется:**
- Playwright mobile viewport smoke (нужен CI runner).
- Hamburger menu в header.
- Tabs на `/topics/[id]`.

## 8. Что дизайн-система говорит правильно

✅ Не пытается быть Material Design (не нужен AI Tutor'у).
✅ Prism/Split сохраняет идентичность через все страницы.
✅ Цветовая схема не перегружена.
✅ Плотная сетка, не расточительная по пространству (что важно для пользователей с большим объёмом контента).

**Мнение:** Текущий дизайн **оставить**, не рефакторить. Менять только там, где есть баги (UI-1, UI-2, UI-3) и accessibility (UI-4).
